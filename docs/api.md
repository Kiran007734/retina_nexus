# API surface

Base URL: `/api/v1`

| Group | Endpoints | Purpose |
| --- | --- | --- |
| health | `GET /health` | Service and database liveness |
| auth | `POST /auth/login`, `GET /auth/me` | JWT architecture and current user |
| images | `POST /images/upload`, `POST /images/{id}/quality`, `POST /images/{id}/enhance`, `GET /images/{id}/content` | Validated intake, Image Trust Gate, controlled enhancement and preview content |
| screening | `POST /screening`, `POST /screening/run`, `GET /screening/{id}`, `GET /screening/{id}/result`, `POST /screening/classify`, `POST /screening/analyze-structures`, `POST /screening/explain`, `POST /screening/trust` | Screening lifecycle, end-to-end orchestration, DR classification, retinal evidence, explainability, and RetinaGuard self-checking |
| patients | `GET /patients`, `POST /patients`, `GET /patients/{id}` | Minimal patient records |
| reports | `GET /reports`, `POST /reports/generate`, `GET /reports/{id}`, `GET /reports/{id}/pdf` | AI-to-clinician screening reports and PDF export |
| clinical review | `GET /reviews/queue`, `GET /reviews/{session_id}`, `POST /reviews/{session_id}` | Human review queue, clinician decisions, comments, and audit capture |
| analytics | `GET /analytics/overview` | Operational screening counts and recent activity |
| models | `GET /models` | Registered model versions |
| monitoring | `GET /monitoring/summary?days=30` | System, model, latency, queue, and drift-validation summary |
| datasets | `GET /datasets`, `GET /datasets/{id}`, `GET /datasets/{id}/statistics`, `GET /datasets/{id}/validation` | Dataset registry and governance summaries |

OpenAPI is generated by FastAPI at `/docs` and `/openapi.json`.

## End-to-end screening run

`POST /api/v1/screening/run` accepts an existing `image_id` and optionally a
screening session, stability/counterfactual flags, and additional model
predictions. It returns a complete run artifact containing quality,
classification, retinal evidence, explainability, RetinaGuard, triage, model
versions, and per-stage statuses. `GET /api/v1/screening/{id}` returns the same
artifact for a queued, processing, completed, or failed run.
